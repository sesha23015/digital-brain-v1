---

## 1. Цель эксперимента

Проверить, насколько замечания ИИ-ассистента связаны с особенностями конкретного проекта.

Необходимо определить, какие замечания опираются на реальные функции, потребности и ограничения системы, а какие являются общими рекомендациями, подходящими практически любому проекту.

## 2. Критерии успешности

Критерии оценки:

1. Замечание связано с конкретной особенностью проекта.
2. Ассистент объясняет, почему возникает проблема.
3. Замечание помогает принять практическое решение.
4. Ассистент не придумывает недостатки без оснований.
5. Общие рекомендации не выдаются за выявленные проблемы конкретной системы.

Для анализа замечания разделяются на три категории:

- **Конкретное:** непосредственно связано с особенностями проекта.
- **Частично универсальное:** имеет отношение к проекту, но может применяться и к другим системам.
- **Универсальное:** общая рекомендация без достаточной привязки к рассматриваемой идее.

## 3. Исходный материал

Для проверки использован ответ ассистента на сильную версию идеи из теста №1.

В исходной концепции предусмотрены:

- Управление задачами двух участников.
- Ответственные, сроки и статусы.
- Критерии готовности.
- Зависимости между задачами.
- Интеграция с Google Calendar.
- Хранение научных источников.
- Отслеживание прогресса проекта.

Ассистенту было предложено объективно оценить концепцию, признать её достоинства и указать реальные риски.

## 4. Метод проверки

Из ответа ассистента выделены семь содержательных замечаний.

Каждое замечание оценено по двум вопросам:

1. Можно ли связать его с конкретной особенностью проекта?
2. Помогает ли оно определить практическую проблему или решение?

После этого замечания распределены по категориям.

## 6. Анализ конкретных замечаний

### Замечание №1. Подтверждение совместных задач

**Почему конкретное:**

Система разрабатывается для двух участников, которые могут совместно выполнять задачи.

Необходимо определить, кто имеет право завершать общую задачу и требуется ли подтверждение второго участника.

Замечание связано с реальным сценарием использования приложения.

### Замечание №2. Интеграция Google Calendar

**Почему конкретное:**

В проекте предусмотрено автоматическое согласование встреч через календари двух участников.

Для реализации такой функции действительно потребуется продумать доступ к календарям и работу с событиями.

Замечание связано с конкретной технической возможностью системы.

### Замечание №3. Расчёт прогресса

**Почему конкретное:**

В приложении планируется отображать готовность дипломного проекта.

Однако выполненные задачи могут существенно различаться по сложности и значимости.

Поэтому простой подсчёт завершённых задач может создавать неверное представление о прогрессе.

### Замечание №4. Критерии готовности

**Почему конкретное:**

В дипломной работе есть исследовательские задачи.

Например, задача «Изучить научную статью» считается выполненной, когда сохранены ссылка, аннотация и полезный фрагмент.

Это конкретное правило работы команды, которое необходимо учитывать при проектировании системы.

## 7. Анализ универсальных замечаний

### Риск чрезмерного усложнения

Это замечание относится к проекту, поскольку в концепции предусмотрено много функций.

Однако похожий риск существует практически при разработке любого приложения.

Для большей конкретности ассистент должен объяснить, какие именно функции могут потребовать непропорционально много времени и почему.

### Сравнение с Jira и Trello

Сравнение с существующими сервисами может быть полезным.

Однако в ответе не было подробного анализа конкретных отличий, поэтому замечание осталось общим.

### Проверка обоснованности функций

Это правильный принцип разработки, но сам по себе он не указывает на конкретную проблему.

Ассистенту следует уточнять, какая именно функция вызывает сомнения и каких данных не хватает для подтверждения её необходимости.

**Конкретность критики**

3. Показать возможные последствия.
4. Предложить способ решения, если для этого достаточно информации.
5. Отделять общие рекомендации от обнаруженных проблем.

Не следует выдавать универсальные советы за результаты глубокого анализа конкретного проекта.
