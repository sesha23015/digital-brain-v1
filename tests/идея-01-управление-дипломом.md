# Идея №1 — Система управления дипломным проектом

**Проект:** Веб-приложение для организации совместной работы над дипломом  
**Ассистенты:** Собеседник и Критик  
**Дата:** 14.11.2026  
**Статус:** Проанализирована, решения по замечаниям приняты

## 1. Исходная идея

Создать веб-приложение для двух участников дипломного проекта, объединяющее управление задачами, научные исследования, планирование встреч и контроль прогресса.

**Главная цель:** уменьшить время на организационные вопросы, чтобы больше времени оставалось на сам диплом.

Приложение является вспомогательным инструментом, а не самостоятельным дипломным продуктом.

## 2. Результат работы с Собеседником

Собеседник помог сформировать концепцию сайта из семи разделов:

1. **Главная** — общий прогресс, ближайшие сроки, текущие задачи и встречи.
2. **Канбан-доска** — задачи, ответственные, статусы, приоритеты и критерии готовности.
3. **Карта проекта** — этапы диплома и зависимости между задачами.
4. **Календарь** — Google Calendar, поиск свободного времени и согласование встреч.
5. **Источники** — научные статьи, ссылки, аннотации, полезные фрагменты и связи с задачами.
6. **Аналитика** — прогресс по этапам, выполненные задачи, история работы и первоначально предложенный учёт вклада участников.
7. **Уведомления** — напоминания о сроках, изменениях и встречах.

Собеседник предложил поэтапную реализацию с сохранением Google Calendar в первой версии.

**Результат:** исходная идея превратилась в структурированную концепцию с понятным назначением разделов.

## 3. Результат работы с Критиком

Критик признал концепцию жизнеспособной и не предложил исключать её основные разделы.

Он выявил четыре вопроса:

**1. Google Calendar в первой версии**

Необходимо уточнить механизм согласования встреч: поиск общего свободного времени, выбор интервала и создание события с приглашением второго участника.

**2. Дублирование данных**

Главная, Канбан-доска, Карта проекта и Аналитика используют общую информацию о задачах. Если хранить её независимо, возможны расхождения.

**3. Аналитика вклада участников**

Количество выполненных задач не обязательно отражает реальный вклад, поскольку задачи различаются по сложности и трудоёмкости.

**4. Доставка уведомлений**

Уведомления, доступные только внутри сайта, можно пропустить, если пользователь не открывает приложение.

Дополнительно Критик отметил, что экономию времени от использования сайта пока необходимо проверить.

## 4. Мои решения

| Замечание | Решение |
|---|---|
| Google Calendar в первой версии | **Исправить** |
| Дублирование данных между разделами | **Исправить** |
| Аналитика вклада участников | **Отказаться** |
| Способ доставки уведомлений | **Принять риск** |

Эти решения приняты пользователем после ознакомления с результатами работы обоих ассистентов.

### 4.1. Google Calendar — исправить

**Принятое решение:** исправить.

Предлагаемое уточнение реализации: показывать общие свободные интервалы, позволять выбрать подходящее время и создавать событие с приглашением второго участника.

Google Calendar остаётся в плане первой версии.

**Личное обоснование решения:** не указано.

### 4.2. Дублирование данных — исправить

**Принятое решение:** исправить.

Предлагаемое уточнение реализации: использовать единые данные о задачах и этапах для Главной, Канбан-доски, Карты проекта и Аналитики.

Изменение задачи в одном разделе должно отражаться в остальных.

**Личное обоснование решения:** не указано.

### 4.3. Аналитика вклада участников — отказаться

**Принятое решение:** отказаться.

Из дальнейшей концепции исключается функция оценки или сравнения индивидуального вклада участников.

При этом решение не означает отказ от всей Аналитики: общий прогресс диплома и выполнение этапов остаются в концепции.

**Личное обоснование решения:** не указано.

### 4.4. Доставка уведомлений — принять риск

**Принятое решение:** принять риск.

Зафиксирован риск пропуска уведомлений, если они отображаются только внутри приложения.

Способ доставки уведомлений пока не пересматривается. Необходимость внешних напоминаний можно проверить при использовании системы.

**Личное обоснование решения:** не указано.

## 5. Обновлённая концепция

После обсуждения с двумя ассистентами сохраняются семь основных разделов сайта.

При этом:

- Для Google Calendar уточняется сценарий согласования встреч.
- Разделы используют общие данные о задачах.
- Из Аналитики исключается оценка индивидуального вклада участников.
- Риск пропуска внутренних уведомлений принимается без немедленного изменения функциональности.

Остальные функции остаются в концепции без дополнительных изменений по результатам этого обсуждения.

## 6. Оценка работы ассистентов

Помог структурировать идею, определить назначение разделов и разделить разработку на этапы.

### Критик

Проверил концепцию, признал её сильные стороны и указал на конкретные риски реализации.

**Польза:** обнаружение вопросов, которые не были полностью решены при первоначальном проектировании.

### Совместный результат

Использование двух ассистентов позволило последовательно перейти от разработки концепции к её проверке.

Ассистенты предлагали варианты, но окончательные решения принимал пользователь.
