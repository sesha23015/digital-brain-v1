## 1. Цель эксперимента

Проверить, как наличие персонального контекст-файла влияет на качество ответов искусственного интеллекта.

Я хотела выяснить, будет ли ИИ учитывать мой реальный опыт, инструменты и уровень подготовки или даст универсальные рекомендации, которые подходят любому пользователю.

## 2. Информация в контекст-файле

В файле `обо мне.md` содержатся сведения, которые могут влиять на рекомендации ИИ.

| Область | Информация |
|---|---|
| Образование и навыки | 4-й курс ДГТУ, системная аналитика; начинаю изучать программирование, Git и создание сайтов |
| Мои проекты | «Авторская стоматология», система управления дипломом, Milknews, обучение вайбкодингу |

| Правила взаимодействия | Объяснять термины, давать пошаговые инструкции, не выполнять учебные задания без разрешения, не менять код без объяснений, не придумывать факты |

Таким образом, файл содержит не только общие предпочтения, но и конкретную информацию обо мне, моих проектах и рабочем окружении.

## 3. Методика эксперимента

Я использовала один и тот же основной запрос в двух условиях:

1. **Без контекста** — модель не получала файл `обо мне.md`.
2. **С контекстом** — к запросу был приложен файл `обо мне.md` с указанием использовать его.

**Основной запрос:**

> Помоги мне выбрать небольшой проект для первого самостоятельного сайта. Объясни, почему он мне подойдёт, и предложи первые три шага.

Во втором варианте добавлена фраза:

> Используй приложенный файл как контекст обо мне.

Для сравнения я выбрала четыре критерия. Каждый оценивался от 0 до 2 баллов.

**Максимальная оценка — 8 баллов.**

## 5. Анализ различий

### 5.1. Ответ без контекста

Модель предложила создать универсальный учебный сайт «Мой день» для отслеживания личных задач.

В ответе присутствовали полезные рекомендации, однако проект не был напрямую связан с моей текущей деятельностью.

По моей оценке, основные недостатки:

- Недостаточный учёт моего начального уровня подготовки.
- Недостаточное объяснение технических терминов.
- Неполный учёт инструментов, с которыми я работаю.
- Менее удобный для меня план самостоятельной работы.

**Оценка: 3/8 баллов.**

### 5.2. Ответ с контекстом

Модель предложила сайт «Мои проекты» и связала его с моей деятельностью: стоматологией, дипломом и другими проектами.

В план были включены:

- Формулирование требований к будущему сайту.
- Создание макета в Figma.
- Разработка первой страницы в VS Code.
- Объяснение назначения каждого этапа.
- Постепенное освоение программирования.

**Оценка: 8/8 баллов.**

### 5.3. Главное содержательное различие

| Без контекста | С контекстом |
|---|---|
| Универсальный список личных задач | Планировщик моих реальных проектов |
| Акцент на HTML, CSS и JavaScript | Дополнительно учитывается системная аналитика |
| Начало с подготовки проекта | Начало с определения требований |
| Общие учебные рекомендации | Привязка к Figma, VS Code и моим задачам |

Таким образом, изменились **предмет проекта и последовательность действий**, а не только стиль ответа.

При этом оба ответа содержали некоторые полезные учебные рекомендации. Поэтому результаты нельзя считать доказательством того, что контекст всегда будет улучшать ответы: я сравнила только две конкретные генерации.

## 6. Моё критическое наблюдение

Несмотря на высокую оценку ответа с контекстом, я обнаружила проблему.

В моём контекст-файле указано, что ИИ должен задавать уточняющие вопросы, прежде чем предлагать решение. Однако модель сразу выбрала проект за меня.

После моего замечания она начала задавать вопросы, но продолжала ориентировать обсуждение на уже предложенную идею.

**Мой исходный комментарий:**

> Потом я заметила, что он все равно продвинул свою идею, не задав мне уточняющие вопросы. Возможно проблема промта, где я четко прошу сделать, возможно в том, что он просто не понял файл обо мне, где прописано задавать мне вопросы передет тем, как начинать делать решение. Я ему об этом сказала и он начал задавать вопросы уже, НО он задавал вопросы и подбивал их ПОД СВОЮ ИДЕЮ ВЫШЕ, те он не особо интересовался тем, что мне интересно сейчас для работы, а втюхивал мне свой проект.

Это показывает, что оценка **8/8 относится только к четырём выбранным критериям**, а не ко всем требованиям моего контекст-файла.

## Приложение А. Полный ответ без контекста

**Запрос:**

> Помоги мне выбрать небольшой проект для первого самостоятельного сайта. Объясни, почему он мне подойдёт, и предложи первые три шага.

**Ответ модели:**

Я предлагаю тебе сделать первый самостоятельный проект — сайт для отслеживания личных задач «Мой день».

Это будет небольшой, но полноценный сайт, который ты создашь самостоятельно с помощью VS Code и ИИ. При этом наша цель — не просто получить работающий сайт, а научиться понимать, как он устроен.

### 1. Как будет выглядеть сайт

**Мой день ☀️**

Планируй дела и следи за прогрессом

Прототип

Твой прогресс

1 из 3

Задачи на сегодня

Изучить основы HTML

Создать первую страницу

Добавить стили CSS

Добавить

Попробуй добавить задачу, отметить её выполненной или удалить. Это интерактивный пример того, что мы будем создавать.

### 2. Почему именно этот проект?

Он подходит для первого сайта по четырём причинам:

- Небольшой масштаб. Одна страница, без сложной регистрации, сервера и базы данных.
- Настоящая функциональность. Ты научишься добавлять, удалять и отмечать выполненные задачи.
- Понимание основ. На практике увидишь, за что отвечают HTML, CSS и JavaScript.
- Возможность развития. Позже добавим сохранение задач, фильтры и несколько страниц.

Я бы не начинал сразу со сложного сайта стоматологии: там много компонентов, страниц и логики. На небольшом проекте гораздо легче разобраться, как всё работает, прежде чем переходить к крупным задачам.

### 3. Первые три шага

**1. Подготовить проект в VS Code**

Создай папку `my-day` и открой её в VS Code через WSL Ubuntu. Сначала разберёмся, где находятся файлы и как открывать сайт в браузере.

Результат: готовое рабочее окружение.

**2. Создать внешний вид страницы**

Сделай заголовок «Мой день», поле ввода, кнопку «Добавить» и список из трёх задач. На этом этапе достаточно HTML и CSS.

Результат: красивая страница, пока без работающих кнопок.

**3. Добавить интерактивность**

С помощью JavaScript научи кнопку добавлять задачи, а чекбоксы — отмечать их выполненными.

Результат: первый работающий сайт.

### 4. Как предлагаю учиться

Я буду выступать в роли преподавателя, а не просто генерировать весь код за тебя.

Сначала объясняю понятие простыми словами, затем показываю небольшой пример. После этого ты выполняешь задание самостоятельно, а я проверяю результат, объясняю ошибки и даю следующую задачу.

Первый вопрос перед началом:

Начать с HTML, CSS и JavaScript, чтобы понять основы

Сразу использовать React и TypeScript, изучая их по ходу

Начать обучение

Для первого самостоятельного проекта я рекомендую первый вариант. Так ты быстрее поймёшь фундамент, на котором строятся и React, и более сложные сайты.

- Знакомая предметная область. Ты уже умеешь управлять проектами и структурировать задачи. Поэтому сможешь сосредоточиться на программировании.

Не будем сразу добавлять регистрацию, сервер или сложную базу данных.

### 3. Первые три шага

**Шаг 1. Сформулировать требования**

Запиши, кто будет пользоваться сайтом, какие задачи он решает и какие функции обязательны.

Зачем: научишься превращать идею в понятное техническое задание.

Ориентир: 30–45 минут

**Шаг 2. Нарисовать макет в Figma**

Размести заголовок, карточки проектов, задачи и кнопки. Достаточно одного экрана.

Зачем: поймёшь, как интерфейс устроен до написания кода.

Ориентир: 1–2 часа

**Шаг 3. Создать первую страницу в VS Code**

Начни с HTML (структура страницы) и CSS (её оформление). Затем перейдём к JavaScript для работы кнопок.

Зачем: увидишь, как макет превращается в работающий сайт, и разберёшься, за что отвечает каждая часть кода.

Ориентир: 2–4 часа

### 4. Как будем учиться

Я предлагаю работать по принципу «сначала понимаешь — затем делаешь — потом проверяем».

Я не буду сразу генерировать весь сайт за тебя. Вместо этого объясню нужные инструменты, дам небольшие практические задания, проверю твои решения и помогу исправить ошибки.

Для первой версии ориентир — 5–8 часов работы, распределённых на несколько занятий. Это приблизительная оценка, а не жёсткий срок.
